# ローカルネットワーク上のマシンのアドレス用証明書

スマートフォンやブラウザが信頼する `https://192.168.0.180` を実現する方法です。インストール固有の認証局を使い、公開 DNS に名前は不要です。**任意で、初期状態はオフ**です。`tls` プロファイル（名前を使う、Caddy 自身の認証局。HTTPS_PAIRING.md を参照）と `lan-ca` プロファイルは今まで通り動作します。サーバーのポート 18080 はローカルネットワークまたは VPN 経由で到達でき、このガイドの内容でインターネットに開放されることはありません。ルーターで転送すると決めた場合は、先に PUBLIC_ACCESS.md に従ってください。外部からのリクエストを許可するのは、強化された公開モード (`network.public_access`、既定はオフ) です。

## 作られるもの

`scripts/armor_lan_cert.py` は、一度だけ **ローカル認証局** を作り、指定したアドレス用に、その認証局が署名した **2 つ目の証明書** を作ります。

* `~/.armor/lan-ca/ca.crt`: 認証局の証明書（公開用。スマートフォンやコンピューターにインストールするもの）。
* `~/.armor/lan-ca/ca.key`: 認証局の秘密鍵。このフォルダー（モード 0700、鍵は 0600）にとどまり、表示されず、プログラムがコピーすることもなく、リポジトリやパッケージに含まれることもありません。
* `leaf.crt`、`leaf.key`、`fullchain.pem`: アドレス用の証明書（プライベート IPv4 アドレス、追加した `.lan` / `.local` の名前、127.0.0.1）とその鍵。

認証局は自身の証明書内の名前制約によって制限されています。保証できるのはプライベートアドレスと `.lan` / `.local` の名前だけなので、鍵のコピーが盗まれても、それを信頼する機器に対してインターネット上のサイトになりすますことはできません。プログラムは公開アドレスを拒否します。

## 手順

1. **まず確認します。** `python3 scripts/armor_lan_cert.py plan --ip 192.168.0.180 --name armor.lan` は、何が作られるかを表示するだけで、何も変更しません。
2. **有効にして作成します。** `python3 scripts/armor_lan_cert.py setup --ip 192.168.0.180 --name armor.lan --enable`。`--enable`（または `~/.armor/lan-ca/lan-ca.json` の `"enabled": true`）がなければ拒否します。初期状態はオフです。再実行すると、アドレスが同じで残りが `renew_days` 日を超えている間は認証局と証明書を保持します。アドレスが変わった場合は同じ認証局で新しい証明書を作るため、機器側は変更不要です。
3. **プロキシに証明書を渡します。** バリアント `caddy/Caddyfile.lan-issued` を使います。これは `/lan-certs/leaf.crt` と `/lan-certs/leaf.key` を提供します: `ARMOR_LAN_CADDYFILE=./caddy/Caddyfile.lan-issued ARMOR_LAN_CERT_DIR=$HOME/.armor/lan-ca docker compose --profile lan-ca up -d`。フォルダーは読み取り専用でマウントされます。この 2 つの変数がなければ、プロキシは Caddy 自身の認証局を使い続けます。
4. **各機器に認証局を一度インストールします。** `python3 scripts/armor_lan_cert.py export-ca --out armor-lan-ca.crt` が公開証明書を書き出します。Android: 設定 > セキュリティ > 暗号化と認証情報 > 証明書のインストール > CA 証明書。iPhone: ファイルを開いてプロファイルをインストールし、設定 > 一般 > 情報 > 証明書信頼設定 でオンにします。Windows: ダブルクリックして「信頼されたルート証明機関」にインストールします。Linux: `/usr/local/share/ca-certificates/` にコピーして `update-ca-certificates` を実行します。
5. **確認します。** `python3 scripts/armor_lan_cert.py fingerprint` は認証局の SHA-256（壁面パネルが固定するもの）を表示します。`--spki` を付けると公開鍵のピン（スマートフォンアプリが固定するもの）を表示します。信頼する前に、機器が表示する値と照合してください。

## 設定ファイル

`~/.armor/lan-ca/lan-ca.json`（すべて任意。範囲外や未知の値は推測せずエラーになります）: `enabled`（false）、`ca_days`（3650）、`leaf_days`（397。一部の証明書では 398 日を超えるとブラウザやスマートフォンが拒否します）、`renew_days`（30）、`curve`（`prime256v1` または `secp384r1`）、`name_constraints`（true）。`ARMOR_LAN_CA_DIR` でフォルダーを移動できます。

## 知っておくこと

* `ca.key` を持つ人は、その認証局を信頼する機器が受け入れる、プライベートアドレス用の証明書を発行できます。フォルダーは自分だけで保管し、他の秘密と同様にバックアップし、リポジトリには決して置かないでください。
* `remove` はフォルダーを脇に退避します（`lan-ca.removed-<時刻>`）。何も削除されません。古い認証局をインストールした機器は、それを削除してください。
* これらは CM5 上では実行されていません。テストは使い捨てフォルダーで openssl を使って認証局と証明書を作り、チェーンがそのアドレスでは検証でき、別のアドレスでは検証できないことを確認します。

## Studio から

管理エージェントがインストールされていれば、管理者は Studio (設定 > セキュリティ) から認証局を作成・更新・置き換えできます。常にメンテナンス認証アプリのワンタイムコードが必要です。エージェントの `POST /v1/lan-ca` の `action` は、`setup` (アドレス用の認証局と証明書。オプションをオンにします)、`renew` (同じ認証局での新しい証明書)、`rotate` (認証局を脇に置いて新しく作ります。すべての機器で再インストールが必要です) のいずれかです。`GET /v1/lan-ca` は認証局と証明書の残り日数を返し、終了まで `renew_days` 以内のものを `expiring` に列挙します。Studio はそれを警告として表示します。エージェントが認証局の鍵を読み取ったり、送ったり、表示したりすることはありません。有効期間と `renew_days` は `lan-ca.json` にあります。
