# 机器的自动安全更新

维护助手（`armor_maintenance_agent.py`，用 `--with-maintenance` 安装）通过 `unattended-upgrades` 保持机器操作系统的安全，并且仅限发行版的**安全源**：不装普通更新、不装小版本更新、不清理内核。它**默认开启**，每一项都是 Studio 中的设置（配置 > 更新 > 自动安全更新）。

## 它做什么

* 根据设置写出 `/etc/apt/apt.conf.d/52armor-security-updates`，并且绝不允许该软件包重启机器：`Automatic-Reboot` 始终为 `false`。重启由助手决定。
* 记录已应用的内容（读取自 `unattended-upgrades` 的日志；Studio 显示最近几次运行）。
* 每次运行后检查每个已安装的 A.R.M.O.R. 服务是否在运行；没有运行的会重启一次，Studio 会显示哪些曾经停止。不会悄悄进行：助手的日志中有警告。

## 重启

有些更新需要重启。“更新需要重启时”有两个取值：**从不自动**（Studio 提示有重启待执行，您在合适时重启）和**仅在时间窗口内且没有布防时自动重启**（默认，本地时间 03:00-05:00）。后者只有在以下条件全部满足时助手才会重启：时间窗口已开始、没有其他操作在运行、服务器答复系统和任何报警主机都没有布防。服务器不答复则视为已布防，机器继续等待。Studio 会显示尚未重启的原因。

## 风险

您没有要求的重启会让服务器、代理和 Studio 停止一两分钟：布防中的报警系统在这段时间不会通报任何信息（主机仍独立保护房屋，但没有人会知道）。因此默认在有任何设备布防时绝不重启，也因此提供了“从不自动”。安全更新偶尔也可能弄坏某个服务：每次运行后的检查会重启并显示，但仍需有人查看。

## 如何关闭

在 Studio 中：关闭“自动安装安全更新”。如果无法访问 Studio，在机器上把 `$PREFIX/data/maintenance/auto_security_updates.json` 的 `"settings"` 中设为 `"enabled": false`，并重启 `armor-maintenance`；助手随后会写入 `APT::Periodic::Unattended-Upgrade "0"`。只删除 apt 文件不够：助手启动时会重新写入。

## 测试

`scripts/test_maintenance_agent.py` 涵盖仅安全配置、设置校验、跨午夜的时间窗口、已应用内容的记录、服务检查，以及不重启的每种原因（已布防、未知、窗口之外、策略、忙碌）。其中没有任何内容会触及真实机器。
