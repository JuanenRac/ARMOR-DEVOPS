# マシンのセキュリティアップデート自動適用

メンテナンスヘルパー（`armor_maintenance_agent.py`、`--with-maintenance` でインストール）は、ディストリビューションの**セキュリティ用リポジトリだけ**に限定した `unattended-upgrades` で、マシンの OS を安全に保ちます。通常の更新、ポイントリリース、カーネルの整理は行いません。**既定でオン**で、すべての項目が Studio の設定（設定 > アップデート > セキュリティアップデートの自動適用）で変えられます。

## 動作

* 設定から `/etc/apt/apt.conf.d/52armor-security-updates` を書き出し、パッケージによる再起動は決して許可しません（`Automatic-Reboot` は常に `false`）。再起動はヘルパーが判断します。
* 適用した内容を記録します（`unattended-upgrades` のログから読み取り、Studio に直近の実行を表示）。
* 実行のたびに、インストール済みの A.R.M.O.R. サービスがすべて動作中か確認します。止まっているものは 1 回だけ再起動し、止まっていた内容を Studio に表示します。黙って行うことはなく、ヘルパーのジャーナルに警告が残ります。

## 再起動

アップデートによっては再起動が必要です。「アップデートが再起動を必要とするとき」の設定は 2 つです。**自動では再起動しない**（再起動待ちを Studio が知らせ、都合のよいときに自分で再起動）と、**時間帯内で、何も警戒していないときだけ自動で再起動**（既定、現地時間 03:00〜05:00）です。後者では、時間帯に入っている、他の操作が実行中でない、サーバーがシステムにもどの警報パネルにも警戒がないと答えている、のすべてが成り立つときだけ再起動します。サーバーが答えない場合は警戒中として扱い、待ちます。まだ再起動していない理由は Studio に表示されます。

## リスク

頼んでいない再起動は、サーバー、ブローカー、Studio を 1〜2 分止めます。その間、警戒中の警報システムは何も通知しません（パネルは自力で家を守り続けますが、誰にも知らされません）。そのため既定では何かが警戒中の間は再起動せず、「自動では再起動しない」も用意されています。セキュリティアップデートがまれにサービスを壊すこともあります。実行後の確認で再起動して表示しますが、人が確認してください。

## オフにする方法

Studio で「セキュリティアップデートを自動でインストールする」をオフにします。Studio に届かない場合はマシン上で `$PREFIX/data/maintenance/auto_security_updates.json` の `"settings"` 内に `"enabled": false` を設定し、`armor-maintenance` を再起動します。ヘルパーは `APT::Periodic::Unattended-Upgrade "0"` を書き出します。apt のファイルを消すだけでは足りません。ヘルパーが起動時に書き直します。

## テスト

`scripts/test_maintenance_agent.py` は、セキュリティのみの構成、設定の検証、日付をまたぐ時間帯、適用内容の記録、サービスの確認、再起動しない各理由（警戒中、不明、時間帯外、方針、実行中）を確認します。実機には一切触れません。
