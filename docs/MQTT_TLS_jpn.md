# ブローカーとの通信を暗号化する(TLS 上の MQTT) - 任意、手順どおりに

言語: [English](MQTT_TLS.md) · [Español](MQTT_TLS_spa.md) · [Deutsch](MQTT_TLS_deu.md) · [Français](MQTT_TLS_fra.md) · [Italiano](MQTT_TLS_ita.md) · [中文](MQTT_TLS_zho.md) · [Português](MQTT_TLS_por.md)

**初期状態ではオフです。** 現在、ノードは家庭内ネットワークで暗号化なしの MQTT(ポート `18883`)でブローカーと通信しており、このガイドに従わない限り何も変わりません。オンにすると、通常のポートの隣に**2 つ目の入口**(`8883`、TLS)が追加されます。通常のポートは、あなたが取り外すと決めるまで残ります。

証明書はインターネットから取得しません。この設備は、ブローカーを動かすマシン上で**独自の認証局**を作ります。`mqtts://` を使うよう設定されたノード(またはサーバー)は**その認証局だけ**を信頼し、ブローカーの証明書が接続先の名前またはアドレス向けに発行されたものかを確認します。それ以外(別の認証局、別のアドレス向けの証明書)は拒否されます。

## 1. ブローカーを動かすマシンで

```bash
scripts/armor_mqtt_tls.sh plan --name casa.local --ip 192.168.0.180      # 実行内容を表示するだけで、何も変更しません
sudo scripts/armor_mqtt_tls.sh setup --name casa.local --ip 192.168.0.180
sudo scripts/armor_mqtt_tls.sh status
```

* 証明書は、このマシンの名前とアドレス(ホスト名、`localhost`、`127.0.0.1`、IPv4 アドレス)と、指定した `--name` と `--ip` を保証します。**ノードはそのうちの 1 つに接続します**(`mqtts://192.168.0.180:8883`)。ノードが使うアドレスを指定してください。
* **認証局の秘密鍵**はマシン上で作られ、`etc/mqtt-ca`(フォルダ `0700`、鍵 `0600`、root のみ)に残ります。リポジトリには入らず、ブローカーの隣にも置かれず、マシンの外に出ません。ブローカーには自分自身の鍵だけが渡されます。
* `setup` はブローカーを再起動します(新しいリスナーには再起動が必要です)。ノードは数秒で再接続します。暗号化なしのポートには触れません。
* `setup` を再実行しても、まだ有効なものは変わりません。アドレスが変わった場合や残りが 30 日未満の場合(ブローカーの証明書は 2 年有効)は、**同じ認証局で新しいブローカー証明書**を作ります。認証局が同じなので、**ノードには触れる必要がありません**。認証局は 10 年有効です。
* このリポジトリのホストファイアウォールを使う場合、それは暗号化なしのポートしか知りません。フィールドネットワークからの `8883/tcp` は自分で許可してください。

## 2. 各ノードで

ノードのパネルの**ブローカー**ページを開きます。

1. アドレスを `mqtts://192.168.0.180:8883` の形で入力します(証明書が保証するアドレスのいずれかである必要があります)。
2. **ブローカーとの通信を暗号化 (TLS)** にチェックを入れます。
3. 認証局の証明書を枠に貼り付けます。`sudo scripts/armor_mqtt_tls.sh export-ca` で取得できます(公開情報です。`-----BEGIN CERTIFICATE-----` から `-----END CERTIFICATE-----` までの 1 ブロックで、約 600 バイト、最大 2 KB)。PEM 形式の証明書 1 つでないものは拒否されます。
4. 保存して再起動します。

ブローカー上のノードのアカウント(ユーザーとパスワード)は変わりません。暗号化がオンのとき、証明書には有効期限があるため、ノードは時刻が合ってから接続します(最長 2 分)。保存済みの予備ブローカーも、スイッチがオンの間は `mqtts://` である必要があり、同じ認証局で検証されます。**オフ**(初期値)なら、ノードはこれまでとまったく同じに動作します。

## 3. このマシンのサーバー

```bash
sudo scripts/armor_mqtt_tls.sh server-tls on      # 環境ファイルの ARMOR_MQTT_URL=mqtts://localhost:8883 と ARMOR_MQTT_CA_FILE
sudo systemctl restart armor-server
```

手動の場合: `ARMOR_MQTT_URL=mqtts://localhost:8883` と `ARMOR_MQTT_CA_FILE=/path/to/ca.pem`。ファイルが有効な証明書でない場合、または `ARMOR_MQTT_CA_FILE` が `mqtt://` のアドレスと一緒に設定されている場合(暗号化されていないのに暗号化されていると思い込む状態)、サーバーは起動を拒否します。Studio は **設定 > ブローカー** で状態を表示します。通信が暗号化されているかどうかと、認証局のフィンガープリント(`sudo scripts/armor_mqtt_tls.sh status` と比較できます)です。`server-tls off` で暗号化なしのポートに戻ります。

## 4. オフにする

各ノードでスイッチを外し(`mqtt://` のアドレスに戻し)、`server-tls off` を実行してから `sudo scripts/armor_mqtt_tls.sh remove` を実行します。何も削除されません。ブローカーのファイルと設定は古いものの隣に退避され、認証局は残されます(`--forget-ca` を付けるとそれも退避します)。後で `setup` を実行すれば、すでにその認証局を信頼しているノードはそのまま使えます。

## できることとできないこと

* ノードとサーバーに対してブローカーを暗号化し、認証します。ノードに独自の証明書は**求めません**。ノードは引き続きアカウントで自分を示します。
* 家庭内ネットワークでの盗聴やブローカーのなりすましから守ります。ブローカーを公開してよい理由にはなりません。`8883` はインターネットに転送しないでください(`REMOTE_ACCESS.md` を参照)。
* コンピューター上で OpenSSL と Mosquitto 2.0 を使って確認済みです(証明書、2 つ目のリスナー、ハンドシェイク、1 つの認証局への固定、別の認証局や別のアドレスの拒否、サーバーの接続)。**ノードの基板ではまだ確認していません**。マイコンではハンドシェイクに少し時間とメモリがかかります。
