# スマートフォン用の HTTPS：家独自の認証局とペアリング

Android アプリは、他の手段がない間はローカルネットワークで暗号化されない `http` を使い続けます。このガイドは、どこからでも `https` で家に接続でき、スマートフォンが覚える独自の認証局を持つ状態へ進む手順で、将来アプリが `http` を拒否できるようにするためのものです。

## 既定のプロファイル

このリポジトリの `tls` プロファイルは、Studio とサーバーの前に Caddy を置きます。既定は安全な設定です。Caddy 自身の**ローカル認証局**（`tls internal`）、`ARMOR_TLS_HOST` 用の証明書、5 分の HSTS、`https` のみ。いずれもインターネットを必要としません。インターネット上の名前を使う場合は `ARMOR_TLS_ISSUER` にメールアドレスを設定すると、Caddy が Let's Encrypt に証明書を求めます（`REMOTE_ACCESS_jpn.md` を参照）。その場合スマートフォンは証明書を自分で信頼するため、ペアリングは不要です。

## 手順

1. **名前。** スマートフォンが家に接続するときの名前（外部からは動的 DNS の名前、またはローカルネットワークの名前）を選び、`ARMOR_TLS_HOST` に設定します（ルーターが 443 を転送するなら `ARMOR_TLS_PORT=443`）。
2. **起動。** `docker compose --profile tls up -d`（またはパッケージの Caddy を同じ `Caddyfile` で）。サーバーは `ARMOR_TRUST_PROXY=1` と `ARMOR_PUBLIC_ORIGIN=https://<名前>` で動かします。
3. **確認。** `scripts/armor_tls_check.sh <名前> 443 <root.crt>` が、サーバーの応答、名前に対する証明書チェーンの有効性、残り 14 日を超えるか、スマートフォンが固定する鍵を示し、`armor-pin:<名前>:<pin>` の行を出力します。ルート証明書は Caddy のデータ内の `pki/authorities/local/root.crt` です（メンテナンスヘルパーが見つけます。別の場所なら `ARMOR_TLS_CA_FILE` で指定）。
4. **スマートフォンごとにペアリング。** Studio の 設定 > セキュリティ > 外部からのアクセス で *電話を家の HTTPS とペアリング* を開き、名前を入力してボタンを押し、テキストをコピーします。アプリの その他 > セキュリティ に貼り付けます。以後アプリは、この家についてその認証局だけを受け入れ、異なる鍵は拒否して知らせます。
5. **すべて試す。** 各スマートフォンで、自宅 Wi-Fi とモバイルデータの両方で、サインイン、カメラ、警戒、アラーム、プッシュを確認します。
6. **そのあとで**初めて、所有者は新しいビルドでアプリの暗号化されない `http` を禁止できます（`cleartext=false`）。すべてのスマートフォンをペアリングして試すまでは、そのままにしてください。

## 知っておくこと

* pin は認証局の**公開**鍵の SHA-256 です。秘密ではありませんが、スマートフォンに渡す人が何を信頼するかを決めるため、管理者にだけ表示され、アプリが示す内容と比較すべきです。
* Caddy は家の証明書を自動更新します。認証局は約 10 年有効で、置き換えられた場合（Caddy のデータフォルダーが新しい場合）は pin が変わり、再度ペアリングが必要です。
* 認証局の秘密鍵はマシンの外に出ず、A.R.M.O.R. も読み取りません。
* ペアリング済みのスマートフォンが異なる鍵に出会うと接続を拒否します。それが目的です。再ペアリングするには、アプリで pin を忘れさせ（その他 > セキュリティ）、新しいテキストを貼り付けます。

## マシンでのテスト（所有者向け）

`scripts/armor_tls_check.sh` が CM5 で成功すること。ペアリング用テキストが Studio とスクリプトの出力で同じであること。自宅 Wi-Fi でペアリングした電話がモバイルデータでも接続できること。`systemctl restart caddy`（またはコンテナ）の後に再ペアリングが不要であること。
