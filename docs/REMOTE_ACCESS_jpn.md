# 家の外から A.R.M.O.R. を使う - 手順

ルール：**入口は 1 つだけ**、そして**アドレスではなく名前**を使います。MQTT ブローカーとノードは決してインターネットに公開しません。

## 1. 入口を選ぶ

* **A. VPN（推奨）**：サーバーを動かすマシンに WireGuard か Tailscale を入れます。外出先ではスマホが VPN に入り、家と同じように動きます（各ノードのパネルも）。プロバイダーが専用の公開アドレスをくれない場合（CGNAT）は、何も開けずに使える Tailscale が使えます。
* **B. HTTPS**：本物の証明書付きのリバースプロキシ（このリポジトリの `tls` プロファイル）をルーターの 1 つのポートに置きます。どのブラウザーからでも便利です。ポリシーを「operate」にして、管理は家か VPN だけにしてください。

## 2. アドレスに追従する名前

公開アドレスは固定のこともあれば、時々変わることもあります。どちらでも**名前**（DuckDNS、No-IP、ルーターのダイナミック DNS、独自ドメイン）を使い、アドレスが変わったら更新する仕組み（ルーターのクライアント、またはマシン上の `ddclient`／DuckDNS のスクリプト）を用意します。TTL は短く（60〜300 秒）。スマホ、Studio、VPN は常に名前を使います。

## 3. ルーターで

サーバーのマシンへ転送するのは**ポート 1 つだけ**：B なら `443/TCP`（証明書が本物なら確認用に `80/TCP` も）、A の WireGuard なら `51820/UDP`。`1883`、`8883`、ノードのポートは決して転送しません。

## 4. サーバー（Docker）で

`.env` に：

```
ARMOR_TLS_HOST=casa.duckdns.org          # あなたの名前
ARMOR_TLS_ISSUER=you@example.com         # Let's Encrypt に証明書を要求し、自動更新
ARMOR_TLS_PORT=443
ARMOR_TLS_HTTP_PORT=80
ARMOR_TLS_BIND=0.0.0.0
ARMOR_PUBLIC_ORIGIN=https://casa.duckdns.org
ARMOR_TRUST_PROXY=uniquelocal            # サーバーが訪問者の本当のアドレスを見られる
ARMOR_TOTP_REQUIRED=remote               # 外部からは 2 段階認証（先に家の中で設定）
ARMOR_REMOTE_POLICY=operate              # 外部からは閲覧とアラーム操作のみ。管理は家か VPN から
```

続けて `docker compose --profile tls up -d`。CM5 ベンチでは同じ設定が `armor.network.env` にあります（Studio > 設定 > セキュリティが書き込みます）。

## 5. Studio で

設定 > セキュリティ：すべてのアカウントで 2 段階認証（認証アプリ）を有効にし、リカバリーコードを保管し、開いているセッションを確認します。管理者は、信頼するプロキシ、家とみなすネットワーク、ポリシー、外部セッションの有効時間を設定します。

## 6. スマホで

A.R.M.O.R. Control：サーバーに名前（`https://casa.duckdns.org`）を入力し、サインインします（2 段階目としてアプリのコードを求められます）。その他 > セキュリティも確認してください。

## 7. 確認する

**モバイルデータ**のスマホで、Studio かアプリの「サーバーからの見え方を確認」を押します。**外部から**と表示され、本当のアドレスが出るはずです。「家の中から」と出る場合、プロキシがアドレスを渡していません。何かを信用する前に `ARMOR_TRUST_PROXY` を直してください。

## してはいけないこと

ブローカーやノードのポートの転送（「ちょっとだけ」でも）、名前の代わりにアドレスを使うこと、初期パスワードのままにすること、外部からサインインする管理者の 2 段階認証を省くこと。
