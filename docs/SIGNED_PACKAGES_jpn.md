# 署名付きパッケージ: マシンが何をインストールするかの決め方

マシンのメンテナンス用ヘルパー(`armor_maintenance_agent.py`)は、GitHub 上の各リポジトリのリリースから A.R.M.O.R. のプログラム(`server`、`studio`、`network`、`ai`、`voice`、`devops`)を更新します。何かを展開する前に、次の 3 点をこの順に確認します。

1. **ハッシュ:** パッケージの SHA-256 が `armor-<コンポーネント>-<バージョン>.tgz.sha256` の値と一致すること。途中で切れたダウンロードを検出できます。
2. **署名:** `armor-<コンポーネント>-<バージョン>.tgz.sig` には、次のテキストの Ed25519 署名(64 バイト、16 進数 128 桁)が入っています。

   `armor-pkg/1|<コンポーネント>|<バージョン>|<sha256>`

   署名はリリース用の秘密鍵で作られます。ヘルパーは自身のコードに組み込まれた公開鍵(`PACKAGE_PUBLIC_KEY`、ノードのファームウェアが信頼するものと同じ鍵)で検証します。`.sig` がない、または検証に通らないリリースは拒否され(`missing_signature`、`bad_signature`)、システムは変更されません。何も展開されず、何も再起動されません。
3. **アーカイブ:** 絶対パス、`..`、リンク、デバイスファイルは含まれないこと。

GitHub 上のリリースの内容しか変更できない人(アカウントの盗難、公開ツールの悪意ある依存パッケージなど)は、パッケージとそのハッシュは公開できても、署名は作れません。秘密鍵は GitHub に置かれないからです。テキストはファームウェアの `armor-fw/1` ではなく `armor-pkg/1` で始まるため、ファームウェアの署名がパッケージの署名として通ることはありません。またコンポーネントとバージョンを含むため、署名済みパッケージを別のプログラムや新しいバージョンに見せかけることもできません。

検証は純粋な Python(RFC 8032)で行われ、マシンに OpenSSL や追加モジュールは不要です。

## 公開する

```
python scripts/package_component.py server --repo ../ARMOR-SERVER --sign --publish
```

`.tgz`、`.sha256`、`.sig` を作成し、3 つともアップロードします。署名ツールは `~/.armor/sign.mjs`(または `--signer` / `ARMOR_PACKAGE_SIGNER`)で、鍵は `ARMOR_FIRMWARE_KEY` または `~/.armor/firmware_ed25519.pem` から読み込みます。鍵はリポジトリにコピーしません。`--sign` は署名ツールか鍵がないと失敗します。指定しない場合は、両方がそろっていれば署名されます。ヘルパーが信頼する鍵以外は使われません。`--publish` は未署名のパッケージのアップロードを拒否します。

すでに公開済みのパッケージに署名するには、`.sha256` と一緒にダウンロードして次を実行します。

```
python scripts/package_component.py --sign-existing armor-server-0.5.7.tgz --upload
```

ファイル名からコンポーネントとバージョンが決まります。`--upload` は、そのリポジトリのリリース `v<バージョン>` に `.sig` を追加します(`gh` が必要)。

## 緊急時の例外

署名なしでパッケージをインストールしなければならない場合(鍵を紛失したときなど)は、マシンの `armor.maint.env`(`$PREFIX/etc/` 内)に次の行を書き、終わったら削除してください。

```
ARMOR_MAINT_ALLOW_UNSIGNED=1
```

インストールのたびにこのファイルから読み込まれるため、HTTP API やプロセスの環境変数では設定できません。使用されるたびに、ヘルパーはジョブのログと自身のログに `WARNING` を書き、概要は `unsigned_allowed` を報告します。

## 鍵の変更

新しい鍵ペアを作り、新しい公開鍵を `PACKAGE_PUBLIC_KEY` とファームウェア(`fw_trust.hpp`)に入れます。**古い**鍵で署名した `devops` パッケージを公開し(マシンがそれをインストールし、以降は新しい鍵を信頼します)、その後のパッケージは新しい鍵で署名します。

## テスト

`scripts/test_maintenance_agent.py` は、有効な署名、改ざんされたパッケージ、`.sig` の欠落、別の鍵による署名、不正なデータ、例外(ファイルからのみ)、RFC 8032 のテストベクター、ヘルパーの鍵が `fw_trust.hpp` の鍵と同じであることを確認します。使い捨ての鍵を使い、本物の鍵は使いません。
