# 手机用的 HTTPS：住宅自己的证书颁发机构与配对

在没有其他方式之前，Android 应用在本地网络中保留未加密的 `http`。本指南是通向“处处通过 `https` 访问住宅”的路径：住宅有自己的证书颁发机构，手机会记住它，这样应用将来就可以拒绝 `http`。

## 默认配置

本仓库的 `tls` 配置把 Caddy 放在 Studio 和服务器前面。默认值是安全的：Caddy 自己的**本地证书颁发机构**（`tls internal`）、为 `ARMOR_TLS_HOST` 签发的证书、五分钟的 HSTS、仅 `https`。这些都不需要互联网。若使用互联网上的域名，在 `ARMOR_TLS_ISSUER` 中填入电子邮件地址，Caddy 就会向 Let's Encrypt 申请证书（见 `REMOTE_ACCESS_zho.md`）：此时手机自行信任该证书，无需配对。

## 步骤

1. **名称。** 选择手机访问住宅所用的名称（从外部访问的动态 DNS 名称，或本地网络的名称），填入 `ARMOR_TLS_HOST`（若路由器转发 443，则设置 `ARMOR_TLS_PORT=443`）。
2. **启动。** `docker compose --profile tls up -d`（或使用软件包中的 Caddy 与同一个 `Caddyfile`）。服务器以 `ARMOR_TRUST_PROXY=1` 和 `ARMOR_PUBLIC_ORIGIN=https://<名称>` 运行。
3. **检查。** `scripts/armor_tls_check.sh <名称> 443 <root.crt>` 会说明服务器是否应答、证书链对该名称是否有效、是否还剩 14 天以上、手机会固定哪个密钥，并输出 `armor-pin:<名称>:<pin>` 这一行。根证书是 Caddy 数据中的 `pki/authorities/local/root.crt`（维护助手能找到它；若在别处，用 `ARMOR_TLS_CA_FILE` 指定）。
4. **逐台配对手机。** 在 Studio 的 配置 > 安全 > 从外部访问 中选择 *将手机与住宅的 HTTPS 配对*：输入名称，点击按钮，复制文本。在应用的 更多 > 安全 中粘贴。之后应用只接受该机构作为这座住宅的证书颁发机构；不同的密钥会被拒绝并提示。
5. **全部试一遍。** 在每台手机上，用家中 Wi-Fi 和移动数据分别测试：登录、摄像头、布防、报警、推送。
6. **之后**，主人才可以在新版本中禁止应用使用未加密的 `http`（`cleartext=false`）。在所有手机配对并测试之前，保持现状。

## 需要知道的事

* pin 是证书颁发机构**公钥**的 SHA-256：它不是机密，但把它交给手机的人决定手机信任谁，所以只向管理员显示，并应与应用显示的内容比对。
* Caddy 会自动续期住宅的证书。该机构大约十年有效；若被替换（Caddy 的数据文件夹是新的），pin 会改变，手机需要重新配对。
* 证书颁发机构的私钥永远不会离开机器，A.R.M.O.R. 也从不读取它。
* 已配对的手机遇到不同的密钥会拒绝连接：这正是目的。要重新配对，请在应用中忘记 pin（更多 > 安全）并粘贴新文本。

## 在机器上的测试（给主人）

`scripts/armor_tls_check.sh` 在 CM5 上通过；配对文本在 Studio 和脚本输出中相同；在家中 Wi-Fi 下配对的手机用移动数据也能连接；`systemctl restart caddy`（或重启容器）后无需重新配对。
